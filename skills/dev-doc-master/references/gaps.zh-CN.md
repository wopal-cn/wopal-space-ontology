# GAPS 参考 — 项目差距跟踪编写

创建或更新项目级 `GAPS.md`：项目设计目标态与其实现之间分歧的记录。模板：`templates/gaps.md`。

## GAPS 文档是什么

GAPS 文档记录项目实现尚未追上设计的地方。它存在是为规划服务：读者打开它，了解还缺什么、设计与代码已漂移多远、哪些差距值得下一步关闭。

它是**过程文档**，不是设计文档。它度量与设计的分歧；绝不继承设计契约，也绝不重述设计内容。当它跟踪的每个差距都关闭时，文档整体删除——没有差距的项目没有 `GAPS.md`。

文档有三个面：

- **头部**声明它所度量的设计（`Design Source`）。
- **主题组**（`##`）承载差距条目，一个主题对应一个架构区或文档关注点。
- **差距条目**（`###`），每条携带 `Current` / `Target` / `Design` / `Exit`。

## 什么算差距

差距是关于**设计**的陈述，不是关于代码质量的陈述。三种情况符合：

1. **设计要求实现没有的东西。** 载体完全缺失。
2. **设计变了，实现没有跟随。** 载体存在，但实现的是被取代的契约。
3. **设计声明该领域是实验性的。** 实验机制是尚未闭合的设计——形态已勾勒但未定案。把它记为差距，正是把它放上收敛路线的方式；没有条目它会无限期保持实验状态，因为没有任何东西拥有让它定案的工作。

第三种情况容易被忽略，因为设计文本存在且读起来像有意为之。它是有意的——设计命名了方向。它仍未完成，而未完成的设计正是差距跟踪器要呈现的东西。

### 什么不是差距

实现缺陷不是差距。设计清晰、功能已实现、而实现有 bug、缺分支或粗糙边缘时，被度量的距离是代码与其自身意图之间——不是设计与代码之间。那属于 **Issue**，通过 issue 工作流跟踪，到达拥有修复上下文的工程师手中。

检验只有一个问题：**设计在轮廓上是否已满足？** 设计契约已存在于实现中，而问题是在某条路径上行为不正确或不完整，那是 issue。契约本身缺失、或以后续形态存在、或仍属实验，那是差距。

区别重要，因为两条路由以不同方式结束。差距在 Plan 实现缺失契约时关闭；issue 在缺陷被修复时关闭。把缺陷记为差距，会产生一个范围只有一个 bug 的 Plan，以及一个没有设计分析能解决的、充满条目的跟踪器。把未实现的契约记为 issue，会把它淹没在缺陷中，任何阶段规划都找不到它。

## 命名与位置

文件名为 `GAPS.md`，位于项目 `docs/` 目录，紧邻它所度量的 `DESIGN.md`。

```
projects/<project>/docs/
├── DESIGN.md
├── DESIGN-<topic>.md
└── GAPS.md
```

每个项目恰好一个 `GAPS.md`。主题在它内部按 `##` 标题分组——不拆分为独立文件。当文档集大到某个项目的差距不再适合一个可读文件时，那是项目应该被拆分的信号，不是差距应该被打散的信号。

ontology worktree 将其 `GAPS.md` 放在 `.wopal/docs/GAPS.md`，遵循同一规则：紧邻其 `DESIGN.md`。

## 粒度与项目边界

差距、Plan 与 Plan 内的任务，是同一事物的三个视图：一个可以独立交付与验证的工作单元。因此它们共享一条边界规则。

**一个差距是一个构建块。** 差距覆盖一个作为单元关闭的单一功能模块——即 Plan 会作为单个任务承载的同一单元。把一个模块的工作拆到多个差距上，会产生只能一起完成的条目，于是每个都依赖其他、没有一个能独立规划。把不相关的模块合并进一个差距，会产生没有单个 Plan 能关闭的条目。

检验：**能否把这件事作为一个工作单元交给一个实施者，并用一套 Exit 标准验证？** 能，就是一个差距。如果一部分能先落地而其余等待不同工作，那就是两个。

同一项目中修复触及相同代码路径的差距通常是一个差距。共享源文件本身不是合并的理由——一个项目的命令面可能存在于一个文件，而其命令保持独立交付物——但共享必须改变的代码路径是。

**差距绝不跨越项目。** 边界是硬的。目标要求多个仓库变更时，那不是有共享归属的一个差距；而是每个项目一个差距，各自携带自己的仓库必须交付的部分。任何一半都不能由另一半关闭，命名两个所有者的差距会停滞。

这适用于 Plan 与任务的方式完全相同：Plan 属于一个项目，其中的任务属于那个 Plan。需要两个仓库才能关闭的差距跨越了工作无法跨越的边界——在项目线上拆分，然后按真实依赖排序两半。

## 编号

差距标识是 `<PREFIX>-G<n>`：三字母项目前缀、字面 `-G`、序号。示例：`CLI-G1`、`ONT-G3`、`ELL-G1`。

**前缀。** 前缀是归属项目的三字母缩写，一份文档恰好用一个前缀。前缀规则存在只为回答一个问题——哪个项目关闭这个差距——因此它保持项目级，绝不编码区、主题或文档关注点。`CLI-G<n>` 属于 wopal-cli，`ELL-G<n>` 属于 ellamaka，`ONT-G<n>` 属于 ontology 仓库。

**归属跟随修复。** 差距属于代码必须改变才能关闭它的项目——粒度与项目边界中的边界规则，应用到标识上。一份文档用一个前缀，因此前缀编码那个所有者，别无其他。

**序号。** 数字在每份文档中单序列运行，逐 1 递增。新差距取下一个空闲数字，无论它落在哪个主题组。

**不可变性。** 一旦分配，标识绝不重用、绝不重编号。关闭的差距让它的数字退役，因此 plan、issue、commit 中的引用永远可解析。取代已关闭差距的差距取新数字。

编号记录是文档自身的 git 历史。退役数字在删除该条目的提交中可见；没有独立台账要维护，文档正文也没有 `Numbering` 章节。

**重编号既有文档。** 文档前缀早于本规则时——单项目文件中的区前缀（如 `ASSEMBLY-G1`），或同一前缀被两个项目共享——一次通过规范化它们：取归属项目的缩写，应用到每个条目，重写序列使数字按单顺序运行。阶段文档的差距清单与任何引用旧标识的活跃 Plan 在同一次变更中更新。

## 头部

头部承载差距所对照的设计真相：

```
> **Status**: Active
> **Updated**: YYYY-MM-DD
> **Design Source**: `./DESIGN.md` (the design this document measures against)
> **Companion**: <one line describing what this document tracks>
```

`Design Source` 命名本项目差距所对照的权威设计文档。使用 `Design Source`，而非 `Parent Architecture`——GAPS 文档不继承架构契约，它度量与架构的分歧。项目有文档集时，指向主 DESIGN；子设计通过其 `Sub-DESIGNs` 字段可达。

源设计必须是**正式**的（`Active`）。差距是定案目标与当前现实之间的距离，因此对照草稿度量会产生被下一次设计修订作废的差距。设计仍为 `Draft` 或 `Proposed` 时，先提升为 `Active`，再开差距。见 `consistency.md` 中的文档生命周期规则。

`Updated` 每次编辑刷新。

## 差距条目

每个差距是带稳定标题与四个标记部分的 `###` 章节。标签是英文——它们是结构化字段名，质量门按字面匹配。

```markdown
### CLI-G3: `space sync` missing, legacy commands not removed (P0)

**Current**: A user can only push revisions in one direction, and there is no way to preview
what a sync would do before running it. Two older commands cover fragments of this job
and are still what users reach for.

**Target**: One `space sync` command moves work both ways — staging the space's own changes
upward first, then pulling the latest downward — with a preview before anything is applied.
The two older commands are gone, so there is one obvious command to run.

**Design**: `./DESIGN.md` (Space Lifecycle).

**Exit**:
- [ ] Running `space sync` without confirming shows a preview and changes nothing
- [ ] Running it on a space with uncommitted edits stops and says so
- [ ] The two older commands no longer exist
```

差距是为没有打开代码的读者写的。它描述**用户能观察到什么、他们将能做什么**——而不是实现形态。

**Current** 陈述产品用户面前的现状：他们不能做什么、必须绕过什么、什么行为不一致。它以已验证的现实为根基，因此每个主张都能追溯到真实观察——但证据塑造主张，不成为主张。段落读起来像源文件摘要（`function X at path Y is called by Z`）时，是写给错误的读者：重写为用户可见的后果。命名命令或选项没问题，因为用户按名称与之交互；命名内部模块、函数或文件路径不行。

**Target** 来自设计文档并忠实于它。它描述交付体验——差距关闭后用户将能做什么，措辞让从未读过设计的人也能想象结果。设计与实现就"应该"是什么产生分歧时，那是设计问题——先在 DESIGN 中解决，再记录差距。

**Design** 按自身名称指向承载解决方案的文档。读者跟随它获取完整契约；差距条目不复述。

**Exit** 以 checkbox 列出关闭差距的标准。每条描述**可观察结果**——人能运行、观看或检查，然后对是否发生达成一致的事。"命令不再有手写 JSON 分支"不是 Exit 标准；它陈述代码形态，只有阅读源码的作者能确认。"命令的错误响应与 `capability list` 宣传的一致"是，因为它命名了一个观察。交付事实，而非实施步骤，且各自独立可验证。checkbox 是关闭标准，不是进度跟踪器：差距在所有标准满足且其 Plan 达到 `done` 后删除。它们不在原地手工维护。

优先级记录在条目标题中，为 `(P0)` / `(P1)`，让扫描标题的读者无需打开每个差距就看到排序。

## 分组

按主题把差距条目分到 `##` 标题下——读者会沿其寻找差距的维度，如架构区（`## Assembly Model`）或文档关注点（`## Capability System`）。每个 `##` 组是导航，不是分类：它存在是为了让读者不必通读整份文档就能找到相关差距。

文档从头部直达第一个主题组。解释文档是什么或如何编号的散文章节属于本参考，不属于文档正文。

## 末尾章节

文档以 `## Reference Documents` 章节收尾，承载仅参考材料：

- 项目自身未在 `Design Source` 中命名的设计文档。
- 提供信息但不构成约束的关联文档。

头部链接与末尾链接不相交。头部命名的文档绝不在末尾章节再次出现——列出两次暗示一种读者无法解读的义务。

## 与 Capability Roadmap 和阶段的关系

项目 GAPS.md 是差距明细的**唯一真相源**。产品 DESIGN 的 Capability Roadmap 描述产品级能力方向；阶段文档按标识、标题、优先级与设计指针列出其范围关闭的差距，不复述其描述。

这种拆分存在是因为重复的差距描述会漂移。阶段指向差距；项目文档定义它们。能力线之间固有的阶段级前后关系可以留在 Phase；具体 Plan 之间当前的执行依赖与顺序属于 Space Active Plan Graph，不属于 GAPS 或 Phase。

## 差距发现

找差距是有界搜索，不是印象。失败模式是抽样：作者读设计、注意到代码缺少的几件事、然后报告那些。那产生一个没有分母的数字——作者和读者都无法分辨它是 4/4 还是 4/40。

差距通过有界枚举发现。边界来自**变更记录**，而非漫读。

### 以变更记录为锚定范围

差距存在于设计与实现之间。设计被重做时，那次重做是离散、可 diff 的事件——把它用作搜索边界。

1. **找到转折提交。** 设计模型发生变化的提交，而非仅格式化的提交。转折重写设计的语义：模型被替换、机制被调换、结构层被移除。文档重命名、头部规范化与标题重排是格式化，不移动任何东西。
2. **跨越转折对设计做 diff。** `git diff <pivot>^ <head> -- <docs>` 得到发生变化的精确设计主张集。这就是枚举：每个语义上变化的设计陈述都是要对照实现检查的候选。
3. **把 diff 归为变更主题。** 把原始 diff 折叠成几个命名主题（模型替换、新机制、命令面变化、能力归属移动）。主题是检查清单单元——它们跨越许多小提交存活，并让审计可控。

未发生重做、设计只是比代码老时，改以设计文档自身为锚：逐章节枚举其陈述。

### 对照实现验证每个主题

对每个主题，在每个受影响项目中定位实际载体，并带证据记录判断：

| 判断 | 含义 | 必需证据 |
|---|---|---|
| Landed | 实现与设计主张匹配 | 载体的 file:line |
| Partial | 载体存在但不满足主张 | file:line 加具体不足 |
| Missing | 无载体存在 | 所执行的搜索（grep 了什么、在什么范围） |
| Doc drift | 实现正确，设计文本过期 | 与现实矛盾的 design file:line |

没有 `file:line` 的判断是印象，不是发现。`Missing` 尤其需要陈述搜索，因为只有在搜索范围已知时，缺席证据才有意义。

### 双向扫掠

设计到代码发现未实现的主张。代码到设计发现相反：存在但没有设计陈述支撑的资产、命令与模块。两者都是一种差距——一个是缺失的工作，另一个是缺失的权威。两者都跑，两者都记录。

### 对照既有差距集核对

铸造新标识前，新发现必须对照已记录的差距检查。实现不足往往已被覆盖——读候选差距的 `Exit` 标准，问它们是否已关闭这个发现。

此步骤防止重复跟踪，也防止相反错误：未读就声明"未覆盖"。只有在读过每个相关差距的完整 `Exit` 清单之后，发现才算未覆盖。提到该区域的 `Target` 不算覆盖；具体的 `Exit` 标准才算。

### 收敛

审计完成时每个主题都有判断、每个判断都有证据、每个发现要么映射到既有差距、要么记录为新差距。这就是分母：枚举的主题 = 判断的主题 = 已解释的发现。

把审计报告为主题表加核对结果。信任报告的读者可以重跑 diff 得到相同的主题清单——这正是让结果可检查而非被断言的原因。

## 差距生命周期

差距有两个状态：**open**（存在于 `GAPS.md`）与 **closed**（已消失）。没有第三个状态，没有状态字段——条目的存在或不存在就是状态。

差距在其 `Exit` 标准满足且承载它的 Plan 达到 `done` 时关闭。`Exit` 标准是差距自身的验证陈述；它们在 Plan 执行期间被验证。

关闭流程：

1. 确认差距的 `Exit` 标准全部满足，Plan 处于 `done`。
2. 从 `GAPS.md` 移除差距条目。
3. 让标识退役——数字绝不重用。
4. 差距从 `GAPS.md` 消失时，阶段文档的差距清单条目随之消失。

不要添加 `Status` 字段、"in progress" 标记或"completed"说明。Plan 自身状态已经告诉读者差距正在被处理；GAPS 中的第二个状态复制它并漂移失步。

## 质量清单

- [ ] 文件是项目 `docs/` 中的 `GAPS.md`，紧邻它所度量的 `DESIGN.md`
- [ ] 头部使用 `Design Source`，而非 `Parent Architecture`
- [ ] `Design Source` 指向正式文档（`Active`），绝不是草稿
- [ ] `Updated` 日期是当前
- [ ] 每个标识遵循 `<PREFIX>-G<n>`；前缀是归属项目的三字母缩写，文档恰好用一个前缀
- [ ] 无数字被重用或重编号
- [ ] 每个差距在单项目内关闭；跨项目工作拆为每项目一个差距
- [ ] 每个差距是一个构建块——可作为一个单元交付与验证，匹配 Plan 任务的粒度；无差距需要另一个差距才能完成
- [ ] 正文无 `About This Document` 或 `Numbering` 散文章节——文档从头部直达主题组
- [ ] 每个差距有四个标记部分：`Current` / `Target` / `Design` / `Exit`
- [ ] 每个 `Current` 描述用户可观察的情况；内部模块、函数与文件路径不出现其中
- [ ] 每个 `Target` 追溯到设计文档中的陈述，并措辞为交付体验
- [ ] 每个 `Exit` 描述可观察结果，而非代码形态——读者无需读源码即可确认
- [ ] 每个 `Design` 命名承载解决方案的文档
- [ ] 每个 `Exit` 是可验证关闭标准的 checkbox 清单
- [ ] 优先级标记在每个条目标题中
- [ ] 末尾章节仅参考且不重复头部文档
- [ ] 设计决策未记为差距——那些属于 DESIGN
- [ ] 实现缺陷未记为差距——契约满足但有 bug 的是 issue
- [ ] 每个实验性设计区都被记录，使它有承载到收敛的所有者
- [ ] 任何差距上无状态字段或 "in progress" 标记——存在或缺失就是状态
- [ ] 每个差距都通过 Gap Discovery 中的有界枚举发现，而非印象——搜索范围已陈述且可 diff
- [ ] 铸造新标识前，每个发现都对照既有差距的完整 `Exit` 清单核对

## 更新模式

1. 刷新 `Updated`。
2. 以其前缀的下一个空闲数字添加新差距。
3. 随实现推进修订差距条目。
4. 差距关闭时，按 Gap Lifecycle 移除其条目。不留 "completed" 标记——不再存在的差距就是消失，数字保持退役。
5. 复查文档集：设计变化可能在集中别处关闭或开启差距。
